# 手机 HTTPS 与真实采集

## 准备

1. 手机与电脑接入同一可互通局域网，先停止普通预览窗口，再双击 `Start-Mobile-HTTPS.cmd`。它监听本机全部网络接口的8443端口，仅用于本地测试。
2. 第一次启动会生成 `data/tls/` 下的本机测试CA和服务器证书。生成器会列出证书覆盖的主机名/IP。只将 **local-ca.pem** 交给自己的测试手机；两个 `*-key.pem` 都保留在电脑，不分享、不放入论文附件。
3. 由使用者在手机系统安装并信任该测试CA。不同手机的具体入口不同；应确认颁发者为 MinePath Local Test CA。系统不会自动修改电脑或手机信任库、绕过证书警告或修改防火墙。若无法建立可信连接，先解决证书/网络问题再采集。
4. 用证书列出的电脑局域网IP访问 `https://电脑IP:8443`。手机的 `localhost` 指手机自身，不能代替电脑IP。防火墙若阻拦，由使用者选择需要的本地测试网络范围放行8443；不要为此关闭全部防火墙。
5. 如果电脑IP更换、证书到期，需按新地址重新签发服务器证书；当前生成器保护已存在的CA，不会覆盖它。CA有效期365天、服务器证书90天；不要把证书警告当成正常成功步骤。

## 登记与采集

1. 手机用员工账号登录“我的上报”，复制本浏览器登记码。电脑管理员在“基础管理→登记/换绑采集端”选择该员工，填写登记码、设备名和原因。
2. 停止管理员的模拟数据流，确保该员工没有模拟采集端占用。换绑会终止旧端新观测授权；旧有效期内真实缓存仍逐条校验补传。
3. 手机刷新页面，确认绑定码一致，选择已分配区域、填写目的，点击开启上报；由手机使用者主动同意定位授权，保持页面前台。
4. 未标定时，服务器保存原始经纬度及设备给出的 accuracy，平面坐标为空。管理员使用已知场地基准点在“规则与标定”填写对应经纬度、平面米制坐标和旋转角，再采新点。标定不追溯改写原始记录；真实场区多边形必须重新配置，演示的A/B/C不是校园实际边界。
5. 开始转场和位置采集是两个操作。任务需负责人先下达，员工准备出发时点击开始；到达后申报，负责人核实实际到达时刻并确认。

## 单手机真实验收清单（尚待使用者执行）

- 记录手机型号、系统/浏览器版本、时间、天气/遮挡与定位授权条件，固定点采样与两次相同路线分别记录。
- 固定点记录计划样本数、取得数和低质量数；只有已标定的有效点才参与米制评估。
- 在采集过程中短暂断网；页面持续实际收到定位回调时才缓存。恢复网络后检查原观测时间与接收时间，不应凭空补齐缺失时段。
- 锁屏/切后台后检查是否出现中断，明确记录手机行为，不能承诺后台不中断。
- 无位置时发起求助；离线保留待上传；恢复后检查只有一条求助。可附一张有效照片。
- 查看开始/停止、换绑和服务器结束的边界，核对补传拒绝反馈。
- 分别导出浏览器来源统计与模拟来源统计；真实观测仍是浏览器声明来源，不代表防伪认证。

本次开发验证没有代替用户在手机上接受定位权限，没有采集用户真实位置，也没有完成现场精度验证。
