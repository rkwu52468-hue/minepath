## 历史版本证据

下列数字来自本地项目已经完成的测试记录，保留各版本和协议的边界。公开仓库从当前工作文件建立新的 Git 历史，原本地提交编号仅用于证据追溯。

### v1.1 历史轨迹查询

- 固定输入 100000 条模拟观测，查询 E001，返回 3334 点。
- 固定时钟 1800000000，查询范围 0 到 1800000001，limit 10000。
- 本机 Waitress 4 线程，无并发写入与 SSE；3 次预热后测量 31 次完整 HTTP 响应及 JSON 解码。
- 原基线中位耗时 115.4959 ms，优化后重复查询 19.4540 ms，降低 83.1561%。
- 另一次 15 请求的无缓存诊断中位耗时 53.2153 ms，协议不同，不能替换重复查询结果或据此承诺所有请求小于 40 ms。
- 缓存按身份、权限和参数隔离，TTL 10 秒，上限 6 项、每项 2 MiB；查询前重新授权，结合 SQLite 提交版本变化失效。优化同时采用区域归属的批量读取。
- 输入 SHA256 `f5c500b0415533dc3c293373498c6622555cfcbbbe18f7ee4882e5b402945857`。
- 规范化响应 SHA256 `06de0e2d2e29e6061d1ffc76e67d901ca13d9bc7c861d1816d8dca2ba846edf3`。
- 5 轮实验保留 3 轮、放弃 2 轮；原有 25 项业务测试与 27 项轨迹响应契约共 52 项保护检查，另有 9 项缓存一致性检查。

公开版本可先生成模拟输入，再执行 `python tools/track_eval.py` 测量当前实现；不要使用 `--freeze` 覆盖冻结契约。历史基线实现不随此公开快照发布，当前机器跑出的耗时不保证与原测试一致。

12 项固定验收从 2 项通过，经两轮实现达到 12 项通过；同时运行当时的 52 项保护检查，共 64 项，不再重复加算其中的 25 项业务测试。

## 当前公开版本

当前快照还包含巡检及求助代处理功能。`pytest tests` 的实际结果另记于 `docs/TEST_RESULTS.md`；历史的 52/64 项不能直接当成当前总数。

GitHub Actions 配置了 Windows 和 Ubuntu 两个平台，但只有对应远程工作流实际成功后，才代表该平台的 CI 已通过。

## 证据边界

数据为模拟输入，软件测试通过不代表手机精度、真实矿厂部署效果或长期容量已经验证。尚待使用者执行手机前台采集、断网恢复、静止分布、重复路线和遮挡降级测试。
